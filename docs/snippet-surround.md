# 以片段包住選取範圍

選一段 T-SQL，按 **Ctrl+K, Ctrl+S**（或 **工具 → SqlAssist → 以片段包住選取範圍**），
從清單挑一筆片段，選取的內容就被包進它的區塊裡。

## 錨點是 `$surround$`，不是 `$selected$`

樣板裡命名為 `surround` 的那一格就是包夾錨點；「這一筆能不能包夾」沒有另一個欄位可
宣告，樣板裡有沒有那一格就是答案。使用者自訂片段把某一格改名成 `surround`，
它就出現在包夾清單裡。

**沒有選取時它就是一格普通的 Tab Stop**，預設值與說明照舊——`be`、`wl` 直接輸入捷徑
展開的行為完全沒變。有選取時那一格改填選取的文字，並且**不再是可導航欄位**：
已經有內容的格子被引擎選起來，使用者下一個按鍵就會把剛包進去的東西刪掉。
其餘欄位仍是 Tab Stop，所以 `wl` 包夾之後游標落在條件那一格。

刻意不沿用原生引擎的 `$selected$`：那是它的保留字，宣告同名 `Literal` 會與引擎自己的
語意相撞，得在產生原生 XML 時多一層欄位改名的映射——一份只為了沿用別人的字而存在
的映射，改錯就是包夾安靜地填不進去。

## 可以包夾的內建片段

`be`、`ife`、`ifne`、`wl`、`tc`、`cur`、`trn` 七筆，都是[流程控制那一族](snippets.md)；
守門的是 `SqlSnippetDefaultsTests.可包夾的內建片段就是流程控制那一族`，新增時要加一行。
`tc` 包的是 TRY 區塊，`cur` 包的是逐筆處理的迴圈內容。

錨點**只能出現一次**：出現兩次時選取的內容會被複製兩份，而同名欄位的同步是原生引擎
用標記做的，填進去之後那一格已經不是欄位，沒有人會替它同步。

## 縮排分三段

| 這一段 | 誰負責 |
|---|---|
| 選取文字自己的**相對**縮排（巢狀的內層要比外層深） | 保留 |
| 選取文字原本的**共同**縮排 | `SqlSnippetSurround` 去掉，否則包一層就多推一層 |
| 樣板在錨點那一格的縮排 | `SqlSnippetSurround` 補上，引擎只放得好第一行 |
| 整段插入點的**基準**縮排 | `FormatSpan`，與包夾與否無關（見[片段導航](snippet-navigation.md)） |

共同縮排比的是**字元**不是欄數：混用 Tab 與空白時換算需要一個 Tab 寬度設定值，
猜錯的症狀是包夾之後整段偏移，而且沒有任何錯誤。

## 選取範圍的處理

- **跨行的選取一律擴成整行**。拖選時起點與終點多半停在半個字上，而包起來的是*語句*
  不是字串——照原樣包會把第一行的縮排留在 `BEGIN` 前面。擴成整行同時讓「去掉共同
  縮排」有意義：第一行的前導空白這時候才是真的縮排。
- 但**要換掉的範圍從第一行的縮排之後才開始**，要包的文字才從行首算起。那一段縮排
  留在緩衝區裡，`FormatSpan` 才有基準可以補到後續每一行；從第 0 欄換起的話它讀到
  空字串，原本縮在兩層裡的程式碼包一次就跑到最外層。
- **單行選取不擴**：那通常是刻意選了一段運算式。
- **框選不支援**，命令回報停用。那是好幾段不連續的範圍，包起來之後每一段各自成句的
  假設不成立。

## 兩條觸發路徑

與 F12 同一種結構，但結論相反：兩條的終點是同一份實作，哪一條成立都可以。

| 路徑 | 什麼時候走這一條 |
|---|---|
| `SqlShellCommandFilter` 攔 `VSStd2K/SURROUNDWITH` | SSMS 自己把該和絃綁在 `Edit.SurroundWith` 上 |
| 命令表的全域鍵繫結（`Menus.vsct`） | SSMS 沒綁時 |

命令在沒有 SQL 編輯器、沒有選取或沒有可包夾片段時回報**停用**，停用的命令不會被派送，
Ctrl+K, Ctrl+S 就落回 SSMS 原本的行為——而不是變成一個按下去什麼都不會發生的鍵。
濾鏡那一條失敗時直接往下轉，不顯示訊息；命令表那一條走狀態列說明原因。
接線細節見[殼層命令](shell-commands.md)。

## 插入走的是同一條路

包夾沒有第二套插入實作：把選取文字填進錨點之後得到一份衍生片段，交給
[片段導航](snippet-navigation.md)那條原生 session 與同一份降級。填掉錨點之後**沒有剩下
任何欄位**的片段（`be`、`trn`）自動退化成單次緩衝區編輯——復原是一格，也不必付原生
引擎那趟 COM。
