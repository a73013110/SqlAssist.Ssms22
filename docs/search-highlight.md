# 命中導覽

SQL Search 預覽裡「每一處命中都標出來、可以一處一處走過去」那一套：算位置、狀態與呈現
各一份。產品與 provider 契約見 [SQL Search](search.md)，視覺語言見 [UI 準則](ui-guidelines.md)。

## 三份職責

- **算位置**：`Ssms22/Search/SqlSearchDefinition.cs` 的 `SqlSearchDefinitionHighlight`。
  它走 `SearchHit.Matches`——併進來的那幾筆全部算——並對每一筆用
  `MatchProjection.FindAll` 找出片段在定義裡的**每一次**出現。只找第一次的那一版走不到
  第二處，而一個資料行名稱在 `CREATE TABLE` 裡出現一次，在後面那一串
  `sp_addextendedproperty` 裡還會再出現一次。重疊的區段併成一段（打 `Due` 而表上同時有
  `Due` 與 `DueDate` 兩行），文件那一層要的是由小到大且不重疊的區段。
  上限 `Maximum` 落在**標記**上不落在比對上，超過時截斷並由狀態列說出來——少標了幾處卻不說，
  使用者按到最後一處就以為看完了。
- **狀態**：`Core/Matching/MatchCursor.cs`。有幾處、現在第幾處、上下一處與環繞收在一份純邏輯裡；
  散到每一個表面各寫一次的症狀是其中一個按到最後一處就不動了，而另一個會捲回文件開頭。
- **呈現**：`SqlScriptDocument` 兩級高亮（`ScriptResource.Highlight` 與 `HighlightCurrent`），
  `SqlMatchNavigator` 畫那兩顆按鈕與「3 / 7」。

兩級而不是一級：「哪幾處對上了」與「我現在在第幾處」是兩個問題。一般命中是半透明強調色，
底下的語法著色仍讀得出來；目前那一處是**實色**強調色加重算過的字色。差別做成「半透明 vs 實色」
而不是兩種深淺的同一個顏色——深淺差一階的那一版在 150% DPI 的深色主題上分不出來，
而分不出來等於沒有「目前」這個概念。

換「目前」是換那幾個 `Run` 的**資源鍵**，不重建文件：重建一次幾千行的指令碼會讓每按一次都掉影格，
而且選取與捲動位置會一起丟掉。一處命中可能跨好幾個 `Run`（高亮切的是原文位移，著色切的是
詞法單元），所以 `Build` 交出的是「每一處的那幾個 Run」而不是一個錨點。

自動捲動只發生在**換一列的第一次**：整份定義從頭顯示而命中在幾百行之下時，使用者看不出自己
選的這一筆為什麼在清單上。之後的每一次捲動都是他自己按的——工具窗裡的 F3／Shift+F3 與那兩顆
按鈕走同一個入口。F3 只攔在這個工具窗上，查詢視窗的「找下一個」不受影響。
