# 內建名稱辨識

判斷游標下的名稱是哪一種內建名稱。說明內容與表面見[內建說明](builtin-help.md)。

## 三套規則

函式與型別靠**左括號**（下一節）。全域變數靠開頭那兩個小老鼠——`@@` 在 T-SQL 裡
只有這一種意思，位置一概不問。提示與 datepart 反過來，只有在 `WITH (…)`、
`OPTION (…)` 與 `DATEADD(` 的第一個引數裡才算，離開那幾個括號 `NOLOCK` 與 `YEAR`
都只是欄位名；位置問的是建議清單換掉整份清單時同一支 `Core/Completion/SqlArgumentPosition`。

括號那一關排在左括號**之前**，否則 `WITH (INDEX(1))` 的 `INDEX` 會因為後面那個
左括號被當成一次函式呼叫。

多字寫法（`FORCE ORDER`、`OPTIMIZE FOR UNKNOWN`）只認第一個詞，而且由長到短試——
`OPTIMIZE FOR` 與 `OPTIMIZE FOR UNKNOWN` 說的是相反的事。停在後半段不認：往回認要先
知道前面還有幾個詞，而圈得起來的範圍仍然只有半個名稱。

停在 datepart 上帶得出那張 datepart 對照表——那個位置要問的正是「還有哪些值可以填」，
而日期函式已經在用同一張。提示與全域變數沒有對照表，寫過範例的那幾個仍開得起浮動視窗，
只是裡面只有範例那一頁。

`[CONVERT]` 是欄位名，`dbo.CONVERT` 是使用者自己的函式，兩者都不是內建名稱。判斷靠
識別字參考的長度與名稱長度是否一致——原文有方括號或限定詞時兩者必然不同，不必新增 API。

第三道是**左括號**，與自動大寫同一條規則（見[函式與型別](completion-builtins.md)）：
`max(` 在 T-SQL 裡只能是呼叫，而 `SELECT year FROM dbo.Loan` 的 `year` 是資料行名稱，
把它說成 `YEAR()` 是提示自己編的。沒有左括號的關鍵字一律不認，否則 `CREATE TABLE` 的
`TABLE` 會被說成資料表變數的型別。

左括號同時決定 `CHAR`、`NCHAR` 這種同時是函式與型別的名稱算哪一種：有括號先當函式，
查不到才退到型別（`DECLARE @t TABLE (` 與 `nvarchar(200)` 的括號屬於型別）。反過來不
成立——沒有括號的名稱不能退回去當函式解釋。`CAST(x AS char(10))` 的 `char` 仍會被說成
函式，要分得開必須知道游標落在 `AS` 的哪一邊，那是位置分析的工作，不是查表的。

判斷整段在 `SqlBuiltInDocCatalog.TryGetAt`，不在平台接線層：只看文字就決定得了的事
不放在 Ssms22。

判斷排在物件解析**之後**：`SELECT * FROM Format` 停在 `Format` 上時要的是那張表，
不是同名的內建函式。物件解析對內建名稱一定落空，順序反過來會讓同名的資料表被蓋掉。

那 118 個函式現在都寫過用途、範例與文件位址，`SqlBuiltInDocCatalogTests` 逐一比對
`SqlFunctionCatalog.Names` 而不是建議清單那一份，少一筆就是建置失敗。「一半有一半
沒有」自己不會冒出來，看得出來的時候通常是停在那個字上的當下。提示與全域變數仍有
沒補範例的。同一份測試也守住名稱與種類都對得回既有目錄、說明與範例排得下不被自己
的截斷邏輯砍掉。

資源讀不到一律降級成空字典，**不**丟例外：那是建置期的錯，而這條路掛在滑鼠移動的
軌跡上，丟出去就是每停留一次看到一次錯誤，`Lazy` 還會把例外永久快取起來反覆重丟。

線上文件只接受絕對的 https 位址。資源是隨組件發布的，但把字串直接交給殼層開啟是一條
真的會執行東西的路，形狀檢查的成本是零。形狀對不代表連得到，改過 `docsUrl` 後跑
`tools/Check-DocLinks.ps1` 送 HEAD 核對；它要網路，不進離線的文件檢查。
