# 通知提示

全套件共用通知來源，提示顯示在宿主內容區右上角。宿主依序是有焦點的 SQL 編輯區、有焦點的
SqlAssist 視窗（SQL Memory 工具窗與對話框）、最後用過的 SQL 編輯區；切換分頁、F12 開新
查詢視窗或點進工具窗時，同一張卡片改掛到新的宿主。都不可見時不顯示，不退回 SSMS 主視窗。

## 計數與來源

- `Core/Notifications/NotificationCenter` 保存執行中與近期完成的不可變快照。
- 成功才計入「已完成」；失敗另列數字，降級與取消在明細標示。項目到期時分子、分母一起扣除。
- `SqlMetadataCatalog.TryLoad` 在實際查詢入口追蹤，涵蓋預載、快取更新、各層按需載入、
  系統物件與定序。等待共享閘與退避不另計數；同步巢狀查詢合併至外層工作。
  快取命中以 `Trace` 記錄，只進統計不上畫面。
- `SqlAssistPlatformGuard.Begin` 追蹤一般背景工作，三軸由呼叫端明寫；初始化與 F12 在原有
  錯誤處理內接線。`BeginProbe` 不整批追蹤，避免週期性連線探測與無工作的預載呼叫反覆閃現
  提示——「重新確認連線」那一則由該處自己開，不改 `BeginProbe` 的行為。
- 當下已經發生、沒有執行期間的事（擷取被丟棄、容量越過警戒）走 `NotificationCenter.Post`：
  直接以完成狀態入列，不經過 Running，不成為環境父工作，也不被 `joinParent` 接手。上限、
  合併、統計、最近失敗與詳細診斷和範圍釋放時同一條路徑。`Status` 只收已完成的結果，
  傳 `Running` 擲例外；三軸與 `Status` 都沒有預設值。
- 提醒走 `NotificationCenter.Prompt`，規則見下一節。
- 標題與完成後的敘述只有 `Core/Notifications/NotificationCatalog` 一份出處：標題是常數短語，
  物件限定名稱放 `Subject`，發起的文件放 `Document`，資料庫放 `Source`，呼叫端不組字串
  也不自己寫措辭。
  逐項文案見[通知訊息](notifications-messages.md)。
- `Document` 與 `Source` 保存啟動時的名稱，不隨焦點更新；無檔名時 `Document` 用穩定編輯區
  編號，中繼資料層只填得出 `Source`。不保存完整路徑、SQL、認證或例外內容。
- 最近結果最多 100 項，不截掉執行中的工作；最近 30 項失敗可從「關於與診斷 → 通知失敗」
  回看。紀錄只存在記憶體，重開診斷視窗更新列表。

## 三個動詞與提醒

| 動詞 | 用在 | 怎麼結束 |
|---|---|---|
| `Begin` | 有執行期間的工作 | 範圍釋放寫回結果，依保留期限淡出 |
| `Post` | 當下已經發生的事件 | 以完成狀態入列，依保留期限淡出 |
| `Prompt` | 需要使用者決定的事 | 使用者按按鈕或叉號，呼叫 `Resolve` |

前兩種是**活動**；`NotificationItem.Actions` 不是空的就是**提醒**，不另加一軸。

- 內容只來自目錄建好的 `NotificationPrompt`（鍵、標題、訊息、嚴重度、按鈕），三軸照舊由呼叫端明寫。
- 按鈕是 `NotificationAction`：`NotificationActionIds` 的穩定識別字、標籤、Primary／Secondary 與參數，
  每則最多一個 Primary。按下之後呼叫端依識別字處理，決定（例如略過的版本）由呼叫端落地保存。
- 同一個 (`Kind`、`Key`) 取代舊的那一則並換新身分；被取代的不算處理。
- `Resolve(itemId, actionId)` 的 `actionId` 為 null 是叉號，語意是「稍後」：只在這次工作階段收起，
  同鍵的新提醒也不再出現，下次啟動照常送出。
- 提醒不逾時、不合併、不受活動的叉號影響；上限 20 則（丟最舊），不跟最近 100 項搶位置，
  不進工作階段統計、最近失敗與逐次完成紀錄。詳細診斷在處理時寫 `id/kind/key/action`，不寫文字。

當初的取捨見[設計](notifications-design.md#提醒)。

## 合併與工作階段統計

合併與統計是兩件事：合併收攏畫面，統計回答「哪些動作在重複」。合併只影響畫面，
每一次呼叫仍逐次計入統計與詳細診斷。

`Core/Notifications/NotificationMerge` 依 (`Kind`、`Title`、`Subject`、`Document`、`Source`) 合併，
提醒原樣保留，只合併已完成且結果相同的項目：執行中的各自成列才保得住進度感，失敗與降級不併入成功。
代表列沿用群組中最早那一項的 Id、位置與耗時；換成最新的那一項，每重複一次就換一個身分，
畫面又回到每次重畫一列，因此逐次的耗時分佈看統計而不是那一列。`NotificationItem.Repeat`
是這一列代表幾次呼叫，畫面上是接在那一列的 `×N` 徽章；敘述本身只回答措辭。
抬頭的「已完成 (成功數/總數)」與漸層條都以合併後的列數計算：三次相同的成功是一列
`1/1`，不是 `3/3`。

`Core/Notifications/NotificationDigest` 依 (`Kind`、`Title`、`Subject`) 累計呼叫次數、
總耗時、平均、最大、失敗數與降級數。統計不受可見度影響：隱藏的種類、`Trace` 與快取命中
一樣計入，否則預設隱藏的四個高頻種類正是最需要回答的那幾類。鍵數上限 200，之後的新鍵
併進「其他」一列，次數仍然完整，只是分不出是哪幾件事。合併的巢狀查詢不另計一次，
與抬頭計數的口徑相同。只留次數與耗時，不保存 SQL、連線字串、認證或例外內容。

畫面入口與排序見[設定入口](settings-entries.md)。

卡片、動畫、設定頁版面與測試覆蓋見[通知呈現與驗證](notifications-ui.md)。
