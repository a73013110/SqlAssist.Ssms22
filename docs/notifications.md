# 通知提示

全套件共用通知來源，提示顯示在目前 SQL 編輯區右上角；切換 SQL 分頁或分割編輯區時，
舊提示移除，新編輯區呈現同一份通知。無可見 SQL 編輯區時不顯示。

## 計數與來源

- `Core/Notifications/NotificationCenter` 保存執行中與近期完成的不可變快照。
- 成功才計入「已完成」；失敗另列數字，降級與取消在明細標示。項目到期時分子、分母一起扣除。
- `SqlMetadataCatalog.TryLoad` 在實際查詢入口追蹤，涵蓋預載、快取更新、各層按需載入、
  系統物件與定序。等待共享閘與退避不另計數；同步巢狀查詢合併至外層工作。
  快取命中以 `Trace` 記錄，只進統計不上畫面。
- `SqlAssistPlatformGuard.Begin` 追蹤一般背景工作，三軸由呼叫端明寫；初始化與 F12 在原有
  錯誤處理內接線。`BeginProbe` 不整批追蹤，避免週期性連線探測與無工作的預載呼叫反覆閃現
  提示——「重新確認連線」那一則由該處自己開，不改 `BeginProbe` 的行為。
- 標題與完成後的敘述只有 `Core/Notifications/NotificationCatalog` 一份出處：標題是常數短語，
  物件限定名稱放 `Subject`，來源文件或資料庫放 `Context`，呼叫端不組字串也不自己寫措辭。
  逐項文案見[通知訊息](notifications-messages.md)。
- `Context` 保存啟動時的文件名稱或資料庫名稱，不隨焦點更新；無文件名稱時使用穩定編輯區編號。
  不保存完整路徑、SQL、認證或例外內容。
- 最近結果最多 100 項，不截掉執行中的工作；最近 30 項失敗可從「關於與診斷 → 通知失敗」
  回看。紀錄只存在記憶體，重開診斷視窗更新列表。

## 合併與工作階段統計

合併與統計是兩件事：合併收攏畫面，統計回答「哪些動作在重複」。合併只影響畫面，
每一次呼叫仍逐次計入統計與詳細診斷。

`Core/Notifications/NotificationMerge` 依 (`Kind`、`Title`、`Subject`、`Context`) 合併，
只合併已完成且結果相同的項目：執行中的各自成列才保得住進度感，失敗與降級不併入成功。
代表列沿用群組中最早那一項的 Id、位置與耗時；換成最新的那一項，每重複一次就換一個身分，
畫面又回到每次重畫一列，因此逐次的耗時分佈看統計而不是那一列。`NotificationItem.Repeat`
是這一列代表幾次呼叫，畫面上是接在那一列的 `×N` 徽章；敘述本身只回答措辭。
抬頭的「已完成 (成功數/總數)」與漸層條都以合併後的列數計算：三次相同的成功是一列
`1/1`，不是 `3/3`。

`Core/Notifications/NotificationDigest` 依 (`Kind`、`Title`、`Subject`) 累計呼叫次數、
總耗時、平均、最大、失敗數與降級數。統計不受可見度影響：隱藏的種類、`Trace` 與快取命中
一樣計入，否則預設隱藏的四個高頻種類正是最需要回答的那幾類。鍵數上限 200，之後的新鍵
併進「其他」一列，次數仍然完整，只是分不出是哪幾件事。合併的巢狀查詢不另計一次，
與抬頭計數的口徑相同。只留次數與耗時，不保存 SQL、連線字串、認證或例外內容。

畫面入口與排序見[設定入口](settings-entries.md)。

## 呈現與設定

`Editor/NotificationHost` 決定該顯示什麼——可見度、合併、措辭與關閉狀態，每個 SSMS
視窗一份。`Editor/NotificationAdornment` 只負責宿主與定位：捲動與改變大小只走定位，
不重算內容；非作用中的編輯區在事件處理常式就早退。只有提示範圍接收輸入，不搶焦點。

版面在 `UI/NotificationCard.xaml` 與 Code-Behind，列由 `UI/NotificationRow` 建立，
按鈕與字型仍由 `SqlAssistChrome.Notifications` 建立。卡片只認得
`UI/NotificationCardItem`（Id、標題、主體、來源、訊息、狀態、重複次數），不認得
`Core/Notifications`；接第二個來源只要產生同一個記錄。視覺規格見
[UI 準則的通知表面](ui-guidelines.md#通知表面)。

關閉是全域的：提示同時只有一份、跟著作用中的編輯區走，叉號的意思是「這一批我看完了」。
它是呈現端的具名狀態，不是編輯區上的靜態欄位；只隱藏目前批次，不取消工作。明細的展開
狀態同樣在呈現端，切換編輯區不收合。

主題色動態更新；執行中光環、成功勾號、失敗警告、取消叉號各有完整狀態 Tooltip 與輔助
技術名稱。循環動畫只有抬頭那一個，各列的執行中是靜態光環。等待中時鐘已預留於視覺列舉，
通知來源尚無排隊狀態，不虛構等待工作。降級還沒有專屬視覺與抬頭計數，暫時落在取消叉號上。
`NotificationPosition` 預留 `TopRight`／`BottomRight`，目前不新增使用者設定。

漸層條顯示與計數相同的比例，不另占文字列。Chevron 以 200 ms 旋轉，明細以 260 ms
展開／收合，可中途反向。任務名稱獨占文字欄，最多兩行，完成不重新排序；重複次數是同一列
的 `×N` 徽章。來源全部相同時檔名只在抬頭下顯示一次，混合來源改在各列名稱下方。
工作可透過 `NotificationScope.Report` 回報最多 512 字的安全訊息，完成後保留；畫面最多
兩行，其餘在 Tooltip。沒有訊息不預留空白列；失敗與取消顯示簡短說明，不展示例外內容。

「通知與背景工作」設定頁分三段：呈現（啟用、材質、動畫、預設展開明細、延遲、保留時間、
詳細度）、十一個種類開關、結果通道（失敗、部分成功）。moniker 一律
`sqlAssist.notifications.*`，子項都以單一同分類 `enableWhen` 縮排並隨父項停用；
只有「忽略 Windows 動畫設定」縮在「淡入與淡出動畫」底下，其餘都掛「顯示通知提示」。

- 預設立即顯示、成功保留 2500 ms；失敗與降級至少保留 6000 ms。
- 最短可見 800 ms；滑入與淡入 300 ms、淡出並縮小 220 ms，淡出時新工作會從目前狀態接續。
- 每列保持身分；執行中新增列高度展開，已完成的新列只淡入，避免高度歸零遮掉勾號彈跳。
  每項與整體成功均微彈出、失敗短震動，不因別列更新重播。
- 進度條與 Spinner 由 SSMS 強調色推導同色系漸層，邊框、微光及捲軸也跟隨主題。
  成功比例增減以 320 ms 從當前值接續；週期刷新不重啟相同目標。
- 預設展開明細並忽略 Windows 動畫偏好；動畫總開關與高對比仍優先，不改 OS 或其他元件設定。
  已儲存的使用者選項不覆寫，新預設只套用未設定的值。
- 滑鼠停留或鍵盤焦點在提示內時暫停期限，移出後續跑剩餘時間；不修改完成時間，記憶體上限仍有效。
- 空閒與非作用中的編輯區不跑計時器；通知合併回 UI 執行緒。關閉編輯器與套件卸載都解除訂閱。
- 計時器每 100 ms 問一次；內容沒變又沒有項目到期時回上一份快照，不重跑到期清理與投影。

## 驗證與限制

Core 測試涵蓋期限、快照快取與截斷、巢狀與並行工作、失敗／降級／取消、來源保留與記憶體
上限；可見度涵蓋兩軸獨立、每一類都關得掉、`User` 跨得過門檻、四階門檻與種類表的 moniker；
目錄涵蓋依結果產生的敘述、耗時門檻與標題常數的形狀（不含物件名稱與標點、不超過十四個
中文字）；合併與統計涵蓋合併鍵、執行中不合併、失敗不併入成功、`Repeat` 計數、代表列
身分、不受可見度影響與併入「其他」。
WPF 測試涵蓋動態主題、材質回退、定位、列身分、來源去重、訊息、動畫策略、進度與捲動，
另涵蓋卡片介面不出現來源型別、自訂記錄直接渲染、`×N` 徽章、柔影快取、捲動只接到定位、
非作用中不排程刷新與關閉的全域語意；渲染輸出在 `artifacts/theme-qa/notification-qa/`，
不能代替 SSMS 實機驗收。降級與診斷紀錄見[可見度](notifications-visibility.md#降級等級與診斷)。

實機需測：SQL 分頁／分割焦點切換、切到非 SQL 文件、關閉工作來源、淡出途中加入工作、
高對比、減少動態效果、鍵盤展開、長名稱、小編輯區及 100%／150%／200% DPI。
目前不顯示假百分比，不提供取消工作按鈕或持久化歷史。
