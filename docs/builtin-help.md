# 內建名稱的說明

兩個表面，分工與物件結構完全一樣。滑鼠停留提示給一眼看得完的份量：引數順序、
一行用途與一段可以直接執行的範例。看不完的那一半——`CONVERT` 的十六個 style、
`DATEADD` 的十五個 datepart——交給浮動視窗，那裡捲得動也選得起來。

建議清單選到同一個名稱時看到的是同一份內容，因為三個表面問的是同一個目錄、
畫的是同一個建構器。這條路**不查資料庫**，沒有連線也答得出來。

## 完整說明開在哪裡

提示最後一行是「開啟完整說明」與「線上文件」；游標停在名稱上按 **Ctrl+F12** 也一樣，
與物件結構同一個鍵。建議清單開著時選到內建項按**向右鍵**、或停夠久自動展開是第三條。
三條開的都是同一個浮動視窗，錨在同一個名稱上——擺放、縮放、複製與收掉因此只有一套
規則（見[預覽互動](preview-interaction.md)）。

清單那條與物件走同一段選取對帳，所以「這一次要畫什麼」只有一個型別
（`Ssms22/Preview/SqlPreviewSubject`）。各佔一個欄位的症狀是對帳與換內容各長一個
分支，漏掉一個就停在上一個東西。沒有查詢，不走節流。

**裝不滿一個視窗就不開**：對照表或範例其中之一（`SqlBuiltInDoc.DeservesWindow`，同
Ctrl+F12）。`smallint` 只有一行說明，而使用者正在說明面板上看著它，蓋上去等於把它
遮掉；那時向右鍵照常右移游標。

| 分頁 | 內容 |
|---|---|
| 範例 | 那段可以直接執行的範例，沿用指令碼分頁的著色 |
| 對照表 | 一張表一個分頁，例如「style（日期時間）」「datepart 名稱」 |

內建說明沒有指令碼，所以「複製全部」在這裡複製的是目前這張對照表——十六列 style
正是會想貼到別處留著的東西。物件那七個分頁全部收起來，換回資料表時再換回去；
少了那一步的症狀是看過一次 `CONVERT` 之後，每個資料表都帶著一個 style 分頁。

對照表分頁**重複使用**而不是每次重建：建立資料格會連帶建立一份內容選單，
而那份選單會登記在視窗上跟著它一輩子。

## 資料分成幾處，不是一處

| 這件事 | 唯一出處 |
|---|---|
| 函式的簽章 | `Core/Keywords/SqlFunctionCatalog` |
| 型別的一行說明 | `Core/Keywords/SqlDataTypeCatalog` |
| 提示與 datepart 的一行說明 | `Core/Keywords/SqlArgumentCatalog` |
| 全域變數的一行說明 | `Core/Keywords/SqlGlobalVariableCatalog` |
| 用途、陷阱與範例、文件位址、對照表 | `Core/Keywords/BuiltInDocs.json` |

那四份建議清單本來就在用（見[函式與型別](completion-builtins.md)與[變數](completion-variables.md)），
JSON 再抄一次的症狀是清單與提示各說一套，而且沒有任何徵兆。`SqlBuiltInDocCatalog`
負責把它們接起來，呼叫端只問它一個；圖示與標題底下那一行種類文字同樣只有一份。

資源那一筆的**種類**要與名稱的種類對得上才算數：`YEAR` 在函式與 datepart 兩份目錄裡
各有一筆，種類寫錯不會查不到，而是把函式的範例貼到 datepart 上。提示與全域變數那幾筆
因此只寫範例與文件位址，一行說明照樣向目錄要——寫了就是第二份。

對照表寫在資源的 `tables` 區塊，由編號引用：`CONVERT` 與 `TRY_CONVERT` 指向同一組
`dateStyles`／`numberStyles`，四個日期函式指向同一份 `datePart`。整張表抄進每一筆的
症狀是改了一份、其他幾份還是舊的。`datePart` 更是**由 `SqlArgumentCatalog` 組出來**
而不寫在資源裡——那 15 個名稱建議清單已經在用同一份。

表格刻意是一張沒有語意的欄與列，不是每個函式一個型別：style 是「編號、格式、輸出」，
datepart 是「名稱、說明」，形狀差太多，一個函式一個型別的話每補一份對照表都要動
C# 與 WPF 兩層。上限四欄——資料格的欄要繫結到真的屬性，索引子路徑在複製與空欄收合
那條路上讀不出來。

**與建議清單分家是為了成本。** 建立候選清單時每次都要交出上百個建議項，那條路徑只需要
名稱與簽章；用途與範例只有真的要顯示時才有人看，因此放在內嵌資源裡，第一次查詢才解析，
之後查表 O(1)。把說明併進建議項等於讓每一次按鍵都扛著幾十 KB 的字串。

名稱的涵蓋範圍比建議清單**廣**：清單會把與關鍵字重疊的名稱讓給關鍵字目錄，但
`CONVERT`、`LEFT` 正是最常被停上去問引數順序的字。讓開是清單才有的兩難（收進去
`LEFT JOIN` 就從清單裡消失了），提示沒有那個問題，所以查的是完整的 118 筆定義。

## 六種名稱，三套辨識規則

函式與型別靠**左括號**（下一節）。全域變數靠開頭那兩個小老鼠——`@@` 在 T-SQL 裡
只有這一種意思，位置一概不問。提示與 datepart 反過來，只有在 `WITH (…)`、
`OPTION (…)` 與 `DATEADD(` 的第一個引數裡才算，離開那幾個括號 `NOLOCK` 與 `YEAR`
都只是欄位名；位置問的是建議清單換掉整份清單時同一支 `Core/Completion/SqlArgumentPosition`。

括號那一關排在左括號**之前**，否則 `WITH (INDEX(1))` 的 `INDEX` 會因為後面那個
左括號被當成一次函式呼叫。

多字寫法（`FORCE ORDER`、`OPTIMIZE FOR UNKNOWN`）只認第一個詞，而且由長到短試——
`OPTIMIZE FOR` 與 `OPTIMIZE FOR UNKNOWN` 說的是相反的事。停在後半段不認：往回認要先
知道前面還有幾個詞，而圈得起來的範圍仍然只有半個名稱。

停在 datepart 上帶得出那張 datepart 對照表——那個位置要問的正是「還有哪些值可以填」，
而日期函式已經在用同一張。提示與全域變數沒有對照表，寫過範例的那幾個仍開得起浮動視窗，
只是裡面只有範例那一頁。

`[CONVERT]` 是欄位名，`dbo.CONVERT` 是使用者自己的函式，兩者都不是內建名稱。判斷靠
識別字參考的長度與名稱長度是否一致——原文有方括號或限定詞時兩者必然不同，不必新增 API。

第三道是**左括號**，與自動大寫同一條規則（見[函式與型別](completion-builtins.md)）：
`max(` 在 T-SQL 裡只能是呼叫，而 `SELECT year FROM dbo.Loan` 的 `year` 是資料行名稱，
把它說成 `YEAR()` 是提示自己編的。沒有左括號的關鍵字一律不認，否則 `CREATE TABLE` 的
`TABLE` 會被說成資料表變數的型別。

左括號同時決定 `CHAR`、`NCHAR` 這種同時是函式與型別的名稱算哪一種：有括號先當函式，
查不到才退到型別（`DECLARE @t TABLE (` 與 `nvarchar(200)` 的括號屬於型別）。反過來不
成立——沒有括號的名稱不能退回去當函式解釋。`CAST(x AS char(10))` 的 `char` 仍會被說成
函式，要分得開必須知道游標落在 `AS` 的哪一邊，那是位置分析的工作，不是查表的。

判斷整段在 `SqlBuiltInDocCatalog.TryGetAt`，不在平台接線層：只看文字就決定得了的事
不放在 Ssms22。

判斷排在物件解析**之後**：`SELECT * FROM Format` 停在 `Format` 上時要的是那張表，
不是同名的內建函式。物件解析對內建名稱一定落空，順序反過來會讓同名的資料表被蓋掉。

那 118 個函式現在都寫過用途、範例與文件位址，`SqlBuiltInDocCatalogTests` 逐一比對
`SqlFunctionCatalog.Names` 而不是建議清單那一份，少一筆就是建置失敗。「一半有一半
沒有」自己不會冒出來，看得出來的時候通常是停在那個字上的當下。提示與全域變數仍有
沒補範例的。同一份測試也守住名稱與種類都對得回既有目錄、說明與範例排得下不被自己
的截斷邏輯砍掉。

資源讀不到一律降級成空字典，**不**丟例外：那是建置期的錯，而這條路掛在滑鼠移動的
軌跡上，丟出去就是每停留一次看到一次錯誤，`Lazy` 還會把例外永久快取起來反覆重丟。

線上文件只接受絕對的 https 位址。資源是隨組件發布的，但把字串直接交給殼層開啟是一條
真的會執行東西的路，形狀檢查的成本是零。形狀對不代表連得到，改過 `docsUrl` 後跑
`tools/Check-DocLinks.ps1` 送 HEAD 核對；它要網路，不進離線的文件檢查。

開關是「滑鼠停留時顯示內建名稱的說明」，縮在物件結構那一項底下；與物件提示
分成兩個開關，因為關掉它的理由不同——已經熟記 T-SQL 的人只想關掉後者。
