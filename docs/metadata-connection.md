# 目前連到哪個資料庫

中繼資料目錄跟著查詢視窗的連線走，而那條連線的資料庫會變：執行 `USE LibArchive`、
改工具列的下拉選單、重新連線。問 SSMS 一次要一趟 UI 執行緒往返（平常 2 到 7 ms，
它忙的時候實測 1908 ms），所以按鍵路徑不問，只每十秒在背景確認一次。

只靠那一輪輪詢的症狀是：`USE` 執行完的第一份清單仍然列著舊資料庫的物件，
再開一次才換過來，而退過的那一次畫面上完全看不出來。

## 由文字觸發的確認

`Core/Parsing/SqlDatabaseSwitch` 從詞元讀出游標前最後一個 `USE` 指名的資料庫。
與目錄現在那一個不一致時，等得起的路徑先確認再回答——建議清單、`SELECT *` 展開、
F12 與參數提示都跑在背景工作上，晚幾毫秒沒有代價。一致就一次都不問，不一致也
一秒內不重複問；沒有 `USE` 的指令碼完全不多付。

文字只決定**什麼時候再問一次**，不決定答案：指令碼寫著 `USE` 不代表它執行過，
目前資料庫仍然是連線說了算。認錯的代價因此只是多問一次連線，不會變成拿另一個
資料庫裡同名的物件回答——那是[中繼資料護欄](rules-metadata.md)禁止的退法。

按鍵與滑鼠停留路徑照舊不等確認，只在背景排一次，下一輪才有。

**Ctrl+Shift+D** 除了清快取也讓每個查詢視窗重新確認連線。只清內容的話，
換過資料庫之後按下它，重新載入的仍然是舊資料庫的物件，而那正是使用者按它的原因。
