# 純量函式的參數提示

游標停在使用者自訂**純量**函式的括號裡時，浮出一行簽章，目前輪到的引數標成粗體：

```text
SELECT dbo.dtoc(|)
        dbo.dtoc(@ddate smalldatetime) RETURNS varchar(10)
```

開關是「輸入自訂函式的引數時顯示參數提示」，預設開著，見[設定](settings.md)。
括號本身怎麼補見[函式呼叫](function-call-insertion.md)。

## 為什麼只做純量函式

2026-09 實機量測（SSMS 22.9）：SSMS 自己的「陳述式完成 → 參數資訊」對內建函式有，
對 `FROM` 後面的資料表值函式**也有**，只有純量函式一律沒有——連 `Ctrl+Shift+Space`
明示叫用都沒反應。所以這一份只補那一格：其餘位置再浮一份是兩個視窗搶同一個位置，
而 SSMS 那一份知道的還比較多（內建函式的傳回型別會即時繫結）。

判斷依據是 `SqlObjectKind.ScalarFunction`，不是「位置在 `SELECT` 還是 `FROM`」——
資料表值函式放在哪裡都由 SSMS 負責，純量函式放在哪裡都由這裡負責。

## 用平台的簽章提示，不自己開視窗

擺放、跟著捲動、Esc 收掉、與建議清單併存都是平台的事
（`ISignatureHelpBroker`，實作在 `Ssms22/Signatures`）。自己畫一份等於把那些重寫一次，
還會在別人的視窗旁邊多出一套外觀——那正是 [UI 準則](ui-guidelines.md)擋著的事。

平台唯一不懂的是「現在是第幾個引數」：它只知道 session 開在哪裡，不懂 T-SQL 的逗號
與巢狀括號。那一段自己算，在 `Core/Completion/SqlCallSignature`。

## 內容從哪裡來

`AugmentSignatureHelpSession` 是**同步**的，而參數要問中繼資料。所以順序反過來：
先在背景把內容備齊，再叫平台開 session，平台回頭來取時只是把備好的那一份拿走。
在那個方法裡等查詢的話，那一次等待發生在 UI 執行緒上。

讀不到中繼資料就這一輪不顯示，下一個逗號就有了——與[建議清單](completion.md)同一條。
沒有輸入參數的函式（`dbo.fn_Today()`）也不顯示：這一份的用途是指出「現在輪到第幾個
引數」，一個引數都沒有時它沒有話可說，而它擋住的那一行程式碼是真的。

選擇性參數標成「可寫 DEFAULT」而不是「選擇性」：函式只收位置引數，省略的寫法是
`DEFAULT` 這個關鍵字，位置照留。哪些有預設值由 `SqlModuleParameterDefaults` 從定義
讀出來，與 [`EXEC` 骨架](statement-values.md#參數的選擇性從定義讀不從中繼資料讀)同一份。

## 什麼時候浮出來、什麼時候收掉

| 時機 | 做什麼 |
|---|---|
| 從建議清單提交一個純量函式 | 括號補上、游標落進去，同時請出提示 |
| 自己打左括號 | 一律重問——`dbo.f(dbo.g(` 裡面那個是**另一個**函式 |
| 自己打逗號 | 提示還沒開著才問；開著的那一份自己會把粗體移到下一個 |
| 游標離開括號、括號被刪掉 | 自己收掉 |

粗體怎麼移：左括號記成 `ITrackingPoint`，每次游標移動或編輯只掃**左括號到游標**那一段
數同一層的逗號。整份指令碼重新分析一次的話，幾千行的檔案打字就會頓——這也是
`SqlCallSignature` 分成兩支的理由，`Resolve` 要從游標往回找左括號，`TrackArgument`
的起點已經知道了。

引數比參數多時（多打了一個逗號）停在最後一個參數上，不收掉提示：那正是使用者最需要
看到「這個函式只收兩個」的一刻。
