# Query Memory UI v1

入口是 SqlAssist toolbar 的「查詢記憶」與「工具 → SqlAssist → 查詢記憶」。
命令聚焦同一個原生 Tool Window，預設停駐右側；沒有新增全域快捷鍵。
殼層保存停駐位置，獨立預覽的位置另存於 VS 使用者設定存放區。

## 瀏覽與預覽

- 歷史預設全部類型、最近七天、所有連線；可切換執行／草稿、期間及精確伺服器／資料庫。
- 收藏預設全域；伺服器／資料庫分開切換，不合併父層，不按 Pinned 跨頁重排。
- 搜尋區分大小寫、不吃萬用字元；歷史搜尋 SQL，收藏搜尋名稱、說明與 SQL。
- 每頁 50 筆，以 opaque cursor 續頁；同一輪分頁固定時間界線，不重新計算「最近七天」。
  畫面只顯示已載入筆數；換條件取消舊請求並更新世代，晚到結果不能改新清單。
- 列表只取 240 字元預覽。SQL 全文等預覽開啟後才讀，不在清單載入時全數取出。
- 單擊只選取，雙擊／Enter／預覽按鈕開啟獨立非模態預覽；開啟後跟隨選取，等待 220 ms
  才讀全文，不反覆聚焦。手動關閉後單擊不會重開；工具窗隱藏時關閉預覽並取消讀取。
- 預覽沿用 `SqlScriptDocument` 著色及 `SqlScriptTheme` 動態資源，沒有編輯器時使用主題備援。
  不沿用 IntelliSense 空間保留或 popup 生命週期；全文與選取複製映射回原文，換行切換只改顯示。

## 收藏與開新查詢

已有 Revision 的歷史可以加入收藏。Recovery 沒有 RevisionId，首版只能預覽或開新查詢，
加入收藏按鈕停用並解釋限制，不建立假 Session。

收藏 metadata 與 SQL 使用兩個編輯對話框，分別呼叫既有 CRUD 與 SQL 編輯交易。
SQL 編輯是可重用純文字控制項，提供原文／修改狀態／唯讀能力，不含 IntelliSense。
取消未存 SQL 會確認捨棄；儲存期間不允許關閉。衝突保留輸入，要求複製後重新整理；
回應不明也不盲目重送非冪等編輯。刪除須確認，不連帶刪除歷史。

「開啟至新查詢」沿用目前 SSMS 連線，不依歷史或收藏 scope 切換連線、不執行 SQL。
仍走 `SsmsScriptWindow` 與 `TextViewEditCoordinator`，只寫入剛建立且仍空白的編輯器。
沒有可沿用連線時顯示失敗，SQL 仍可複製。

## 生命週期與共用邊界

UI 透過宿主受保護的背景操作存取隔離儲存，不持有 repository。UI 操作、手動整理、
維護與卸載共用閘門；先等待已派送呼叫與 writer 排空，才在背景卸載 AppDomain。
儲存重新開啟會更新世代，舊請求不能在新宿主繼續操作或呈現結果。

停用時不開儲存、不讀取既有資料，只顯示設定入口。工具窗定期讀取記憶體狀態，
顯示啟用失敗、寫入器停止或佇列拒絕；不因此自動重新讀取或重排歷史清單。

字型與樣板遵循[UI 準則](ui-guidelines.md)。共用 SQL viewer／文字 editor 留在 UI，
收藏、版本與儲存流程留在 QueryMemory；不建立另一套視窗框架。
